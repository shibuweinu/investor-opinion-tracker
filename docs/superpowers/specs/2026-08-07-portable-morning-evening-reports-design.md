# 可移植早报、晚报与增量窗口设计

## 目标

把现有单一日报拆成交易日 09:00 早报和 21:00 晚报，新增雪球用户 `7977283243` 为研究博主，并消除个人目录和固定工作区命名对任务执行的影响。全新用户克隆产品仓库后，除个人配置、登录凭据和是否安装本机调度器外，执行与现有用户相同的 onboarding、确认、抓取、核验和报告流程。

## 报告任务模型

远端配置升级为 Schema v2，以 `report_jobs` 保存任意数量的报告任务。每个任务具有稳定 ID，并包含：

- `kind`：`morning`、`evening` 或 `weekly`；
- 是否启用、时区、星期、触发时间；
- 各账号角色的最大历史上下文天数；
- 增量窗口来源；
- 报告侧重点和投递设置引用；
- 是否允许仓位建议。

当前用户包含：

- `morning`：周一至周五 09:00；
- `evening`：周一至周五 21:00；
- `weekly`：周日 18:00。

产品不再把 `data`、`data-daily-news`、`data-weekly` 等目录名称视为业务契约。任务状态统一位于 `<workspace>/.investor-opinion-tracker/jobs/<job-id>/`，所有 Agent 通过 CLI 的任务 ID 操作，不推导或拼接个人路径。

## 增量窗口与上下文

早晚报各自维护成功检查点：

- 早报新增窗口从上一份成功晚报的截止时间开始，到当日 09:00；
- 晚报新增窗口从当日成功早报的截止时间开始，到当日 21:00；
- 周末和节假日产生的内容自然进入下一次早报窗口；
- 某次任务失败或未达到完整性门禁时不推进检查点，下一次成功运行补抓缺失区间；
- 首次运行没有检查点时，研究博主最多回溯 5 天，辅助资讯最多回溯 2 天。

报告可以引用历史上下文，但“本期新增观点、观点变化和统计”只使用增量窗口内帖子。研究博主保留最近 5 天上下文；`7X24快讯` 仍为 `auxiliary_news`，最多保留 2 天且不能计入主观观点、共识、持仓、胜率或独立交易候选。

早报侧重隔夜变化、开盘前风险和观察项；晚报侧重盘中观点、收盘行情核验和次日观察项。两个报告使用不同邮件标题和输出目录，不互相覆盖。

## 新用户与新设备流程

全新 clone 的统一流程：

1. 安装依赖并运行 `init --no-interactive`；
2. 选择 `restore`、`create` 或 `skip`；
3. Agent 展示 landing，并恢复或收集追踪账号、画像和报告任务；
4. CLI 根据 `report_jobs` 创建全部任务状态，不要求用户提供目录名；
5. Agent 展示所有任务摘要并取得明确确认；
6. 用户在本机完成雪球外置浏览器登录；
7. 执行抓取、行情与事实核验、分析和报告；
8. 可选初始化邮箱凭据和本机调度器。

恢复远端配置不会自动获取雪球 Cookie、浏览器登录态、SMTP 授权码或其他设备的调度器。上述内容属于设备级 onboarding，并由 landing 明确列出。未安装定时任务时，用户仍可通过同一任务 ID 手动运行早报、晚报或周报。

## CLI 与 Agent 契约

CLI 增加或调整以下稳定语义：

- `jobs list`：列出任务 ID、类型、计划、状态和最近成功检查点；
- `jobs summary <job-id>`：展示目标、角色、上下文和下一增量窗口；
- `jobs confirm <job-id>`：确认当前任务指纹；
- `jobs run <job-id>`：执行确认后的任务；
- `jobs run-due`：供本机调度器执行当前到期任务；
- `config-pull`：原子生成全部 `report_jobs`，不只生成一份日报草稿；
- `config-preflight`：原子更新全部任务，任何任务校验失败时不应用部分更新。

Codex、Claude、WorkBuddy 和人工终端使用同一 CLI。Skill 不得要求 Agent 直接访问某个用户的绝对路径或复制 launchd 文件。

## Schema 迁移

Schema v1 的 `daily` 自动迁移为 `evening`，保留原 21:00 计划；同时创建默认 09:00 `morning`。`weekly` 迁移为同名任务。迁移先在内存中完成完整校验，成功后一次性写入；失败时保留 v1 配置和现有任务。

v2 仍采用严格字段白名单。旧版 Agent 读取 v2 时必须明确提示升级，不能忽略未知任务或降级覆盖远端配置。

## 调度与可信自动应用

调度器只调用 `jobs run-due`，不内嵌博主、回溯天数或个人目录。macOS 使用 launchd，其他平台可使用 cron、Task Scheduler 或宿主 Agent 自动化；逻辑计划来自远端配置，本机安装行为仍需单独确认。

`trusted_auto_apply` 保持远端偏好加设备级授权的双重开关。预检必须先构造并校验全部任务草稿，再原子替换本地配置。仓库身份、私有状态、Git 身份、Schema 或历史连续性异常时不应用更新。

## 失败处理

- 抓取或核验失败：不推进该报告检查点，不发送正式邮件；
- 早报失败：晚报从最后成功检查点补抓，不假定 09:00 已完成；
- 远端配置不可达：使用上一次已确认安全配置并标注同步失败；
- 多任务配置任一项无效：全部拒绝，不留下部分更新；
- 昵称解析失败：保留账号 ID 和原显示名，不阻断帖子抓取；
- 新设备未登录雪球或未配置邮箱：给出设备级恢复指引，不影响配置导入。
