# 私有 Git 仓库配置同步设计

## 目标

让每位用户把可移植的 Investor Opinion Tracker 个人配置保存到自己控制的私有 Git 仓库，并可在 Codex、Claude、WorkBuddy 或另一台电脑恢复。第一版不建设账号系统、数据库或服务端；仓库托管方负责身份验证和写权限隔离。

默认个人配置仓库名为 `investor-opinion-tracker-config`。当前用户使用 `shibuweinu/investor-opinion-tracker-config`。

## 方案选择

考虑三种方案：

1. 每位用户拥有独立私有配置仓库。隔离边界清楚，无需自建服务端，适合第一版。
2. 所有用户共用一个私有仓库并按目录隔离。Git 仓库权限无法限制协作者只能修改自己的目录，不满足要求。
3. 云端数据库配合用户认证和行级权限。长期扩展能力最好，但当前需要服务端、身份系统和运维，成本过高。

第一版采用方案 1。仓库所有者可以修改自己的配置；其他用户默认既不可见也不可写。用户主动授予 Git 仓库协作者权限后，对方获得的能力由仓库托管方决定，本产品不承诺覆盖这类主动授权。

## 仓库职责

产品代码仓库和个人配置仓库严格分离：

- 产品代码仓库保存 CLI、Skill、文档、Schema 和测试，不保存任何用户实例配置。
- 个人配置仓库仅保存通过 Schema 校验的可同步配置和格式版本。
- 本机工作区继续保存任务状态、抓取结果、报告和运行日志。
- 操作系统钥匙串或浏览器保存登录凭据。

个人配置仓库包含：

```text
investor-opinion-tracker-config/
├── README.md
├── config.json
└── .gitignore
```

`config.json` 使用稳定、Agent 无关的 JSON 格式。首版字段包括：

- `schema_version`
- `tracked_accounts`：雪球主页、显示名和 `research` 或 `auxiliary_news` 角色
- `reports.daily` 与 `reports.weekly`：是否启用、回溯天数和触发计划
- `trader_profile`：交易周期、激进度和风险参数
- `report_preferences`：是否包含仓位建议等非敏感偏好
- `updated_at` 与随机 `revision`

定时计划只同步星期、时间和时区等逻辑值，不同步本机程序路径、日志路径或 launchd plist。

## 永不上传的内容

同步采用字段白名单，不以黑名单过滤。下列数据不得进入配置仓库：

- 雪球 Cookie、Token、浏览器资料和登录态
- 邮箱密码、SMTP 授权码和钥匙串内容
- 抓取原文、缓存、SQLite 状态库、证据包、报告和日志
- 本机绝对路径、设备标识和临时文件
- 环境变量及任何未知扩展字段

导出前必须经过 Schema 序列化；同步命令不得直接复制 `.investor-opinion-tracker` 目录。安全检查发现疑似凭据、未知字段或不允许的文件时，中止提交并给出可恢复提示。

## CLI 与 Agent 流程

新增统一的配置仓库操作，具体命令名称在实现计划中固定：

1. `connect`：绑定已有私有仓库，或在用户明确确认后创建新私有仓库。
2. `status`：显示本地配置、远端配置、同步状态和冲突，不泄露凭据。
3. `push`：校验并导出白名单配置，展示摘要，获得确认后提交和推送。
4. `pull`：拉取远端配置、校验版本并展示变更摘要，获得确认后写入本地草稿。

Agent 安装流程为：初始化产品 → 询问创建新配置或恢复已有配置 → 展示远端配置摘要 → 用户确认 → 写入本地草稿。远端拉取不能绕过现有任务确认门禁；抓取前仍需确认当前任务摘要。

### 新设备首次初始化

从产品代码仓库进行全新安装时，不会静默猜测或自动拉取任何个人配置仓库。`init` 检测到本机尚未绑定远端配置后，必须明确提供三个选择：

1. 从已有私有配置仓库恢复；
2. 创建新的个人配置仓库；
3. 暂时跳过并仅在本地使用。

选择恢复时，程序获取仓库地址、验证当前 Git 身份的访问权限、拉取并展示配置摘要；只有用户确认后才写入本地草稿。选择创建时，仍需按照“创建和权限边界”一节再次确认仓库所有者、名称和私有属性。选择跳过时不进行任何网络或 Git 写操作，用户以后可以从 `connect` 重新进入流程。

`init --no-interactive` 不在终端等待输入，而是返回机器可读的“未绑定远端配置”状态和三个允许动作，由 Codex、Claude、WorkBuddy 等 Agent 逐项询问用户。它不得将历史对话里的仓库地址当作新用户默认值。

允许用户显式提供仓库地址以缩短恢复流程，例如：

```bash
opinion-tracker init --no-interactive \
  --config-repo git@github.com:shibuweinu/investor-opinion-tracker-config.git
```

显式地址只允许程序拉取、校验并展示摘要，不代表用户已经确认导入、抓取或安装调度器。配置导入后，程序根据当前操作系统单独询问是否安装本机日报和周报任务；同步的逻辑计划不会直接复制另一台设备的 launchd、cron 或绝对路径。

GitHub CLI 只作为一种可选适配器。核心同步使用普通 Git 和本地目录，因而其他 Agent 不需要 GitHub 专用插件。创建远端仓库时若缺少登录或权限，程序停止并提供最短人工授权步骤。

## 同步与冲突

每次成功同步记录本机最后同步的 Git commit 和配置 `revision`：

- 仅本地变化：允许推送。
- 仅远端变化：允许拉取。
- 双方未变化：报告已同步。
- 本地和远端均变化：拒绝自动覆盖，展示字段级差异，让用户选择本地版本、远端版本或取消。

首版不做自动字段合并，避免错误合并追踪列表、风险参数或调度规则。任何拉取导致执行相关字段变化时，现有确认失效，任务回到 `draft`。

## 创建和权限边界

程序创建配置仓库前必须展示仓库所有者、名称和 `private=true`，并取得用户确认。创建完成后验证：

- 远端仓库确实为私有；
- 当前身份具有读写权限；
- 远端地址指向预期所有者；
- 首次提交只包含允许的三个文件。

程序不修改组织权限、协作者、分支保护或访问令牌。个人配置仓库不能作为共享多人配置存储；需要共享时应由每位用户复制为自己的仓库。

## 失败处理

- 网络不可用：保留本地配置，不更改同步基线，可继续本地运行。
- 身份失效或无权限：停止远端操作，不反复重试认证。
- Schema 版本过新：拒绝覆盖并提示升级产品。
- JSON 无效或安全检查失败：不导入、不提交，报告具体字段。
- 推送被拒绝：重新拉取并进入冲突状态，不强制推送。
- 创建仓库后初始化失败：保留远端空仓库并清楚报告状态，不上传半成品配置。

## 测试与验收

自动化测试使用本地 bare Git 仓库模拟远端，覆盖：

- 白名单导出及敏感字段、未知字段拒绝；
- 新建、绑定、首次推送和另一工作区恢复；
- 本地变化、远端变化、无变化和双向冲突；
- 拉取后任务确认失效；
- 网络、认证、权限和 Schema 版本错误；
- Windows、macOS、Linux 可移植路径；
- Codex、Claude、WorkBuddy 文档使用同一 CLI 契约。
- 全新设备初始化展示恢复、新建、跳过三个选项；非交互模式返回等价机器可读状态；
- 显式 `--config-repo` 只拉取和展示，不绕过导入、抓取或调度确认；
- 从 macOS 配置恢复到其他设备时不复制 launchd 文件或本机绝对路径。

真实验收使用 `shibuweinu/investor-opinion-tracker-config`：确认仓库为私有，首次提交只包含允许文件；在临时新工作区拉取并还原十个追踪账号、日报与周报规则和交易者画像；确认钥匙串、Cookie、报告、日志及本机路径均未出现于 Git 历史。

## 第一版非目标

- 不提供中心化网页登录或数据库。
- 不同步凭据、抓取内容或报告。
- 不提供多人协同编辑或字段级自动合并。
- 不替用户配置 GitHub 协作者或组织策略。
- 不保证定时任务跨操作系统原样运行；只同步逻辑计划，由目标设备本地安装调度器。
