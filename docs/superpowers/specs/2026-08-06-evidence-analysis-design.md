# 可审计混合分析设计

## 目标

将已确认任务抓取到的帖子转换为可审计证据包，由宿主 Agent 完成语义分析，再输出按博主、行业、股票和分歧组织的日报。不得把所有帖子自动视为正式观点。

## 架构

确定性程序负责清洗、去重、作者归属、内容初筛、显式代码、时间线、行情数据和证据引用；宿主 Agent 负责公司昵称、行业主题、本人观点与转发、观点变化以及多博主一致性。Agent 只能依据证据包下结论，并标记原文明示或 Agent 推导。

`run` 输出 `posts.json`、`evidence-pack.json` 和 `ANALYZE.md`。Skill 要求 Agent 随后生成最终 `report.md`；没有完成语义分析时不得把确定性初筛结果称为交易报告。

## 内容分类

初筛标签包括：明确观点、回复观点、持仓或交易披露、转发引用、事实转述、提问、玩笑情绪和无有效信息。只有前三类默认进入正式证据候选；其余内容保留为上下文。空文本、纯转发和纯提问不得生成交易候选。

## 证据包

证据包包含任务范围、数据完整性、每位博主的抓取数量、候选证据和上下文。每条证据保留帖子 ID、作者、时间、原文链接、原文、分类、显式股票代码、主题关键词和分类理由。

## 报告契约

最终日报必须包含数据覆盖、逐博主核心观点、观点变化、多博主一致与分歧、可交易行业、候选股票、行情时间与来源、催化、风险、失效条件、观察清单和原文证据索引。候选缺少正式观点、有效引用、可信映射、行情或失效条件时必须降级为观察项。

## 仓位建议

任务字段 `include_position_sizing` 默认 `false`。关闭时报告不得给出仓位比例、金额或股数；开启后仍需账户规模、入场价和止损条件，缺失时只能展示风险预算公式。

## 验收

- 235 条真实帖子不会生成 235 条正式观点。
- 三位博主分别统计并保留证据。
- 空文本、纯转发和提问不会成为正式候选。
- 所有证据引用能回溯到 `posts.json`。
- 默认报告分析契约明确禁止仓位建议。
- 新用户确认后可完成抓取和证据准备，Agent 能依据 `ANALYZE.md` 继续生成最终报告。
