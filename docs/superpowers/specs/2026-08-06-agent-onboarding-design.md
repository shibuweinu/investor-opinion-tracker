# Agent-first onboarding 与执行确认设计

## 目标

让首次安装用户沿着一致且可验证的流程完成配置：Agent 安装、展示 landing、询问需求、生成任务摘要、获得明确确认、抓取、行情核验、分析总结，最后再询问是否创建定时任务。系统不得从历史对话静默继承抓取目标，也不得在任务未确认时访问雪球时间线。

## 适用入口

产品以 Agent-first 流程为主，同时保留人工终端入口：

- `opinion-tracker init --no-interactive --workspace <path>` 用于 Codex、Claude、WorkBuddy 等 Agent 安装。它只创建配置、landing 和待 onboarding 状态，不等待终端输入，也不创建默认抓取任务。
- `opinion-tracker init --workspace <path>` 用于人工终端安装。它创建相同状态后进入问答；用户可以退出，稍后继续。
- 两种入口共用同一任务草稿、确认记录和执行门控，不存在绕过确认的快捷路径。

## 首次使用流程

1. `init` 创建 `.investor-opinion-tracker/config.json`、`WELCOME.md` 和 onboarding 状态。
2. landing 告诉用户产品用途、隐私边界、默认值、接下来会询问的问题，以及确认之前不会抓取。
3. Agent 逐项收集：雪球博主主页、回溯天数、报告类型、交易周期、激进度和单笔风险预算。
4. 用户暂不设置画像时，Agent 明确说明将采用 `mixed / balanced / 单笔计划亏损 0.5%`；用户接受后才能写入草稿。
5. CLI 保存任务草稿并输出稳定、可复述的任务摘要，包括目标、时间范围、QPS、报告类型、交易者画像、授权状态和“尚未执行”。
6. Agent 把摘要展示给用户。只有用户对当前摘要作出明确确认后，Agent 才调用确认命令。
7. 确认记录绑定草稿内容的确定性摘要值；任何执行相关字段变化都会令旧确认失效。
8. 抓取入口校验有效确认，通过后连接已登录的外置 Chrome，按 QPS 和时间边界抓取。
9. 完整抓取进入行情核验和分析总结；不完整数据只输出观察项，不给主动仓位建议。
10. 报告完成后询问是否创建定时任务。未得到另一次明确确认时不得创建。

## 状态模型

工作区保存一个不含凭据的任务状态文件：

- `onboarding_required`：尚未形成完整任务草稿。
- `draft`：草稿完整但未确认。
- `confirmed`：当前草稿已确认，可执行一次或按另行确认的计划执行。
- `completed`：本次任务已完成；保留配置供下次生成新草稿。

任务草稿包含：

- 一个或多个雪球主页 URL；
- 回溯天数，默认 5；
- QPS，默认且最大为 1；
- 报告类型 `daily` 或 `weekly`；
- 交易者画像；
- 授权声明状态；
- 创建时间和内容摘要值。

确认记录包含草稿摘要值和确认时间，不保存用户登录态、Cookie、Token、密码或验证码。修改目标 URL、回溯天数、QPS、报告类型、画像或授权状态时，状态恢复为 `draft`。

## CLI 与 Agent 契约

CLI 提供以下语义稳定的操作：

- 初始化工作区，并支持 `--no-interactive`。
- 创建或更新任务草稿。
- 以人类可读文本和 JSON 输出任务摘要。
- 确认当前草稿。
- 查询当前 onboarding/任务状态。
- 在执行前验证确认记录；验证失败必须返回非零退出码和可恢复提示。

Skill 要求 Agent：

- 新工作区不得复用对话中先前出现过的博主作为默认目标；
- 一次只询问一个易回答的问题；
- 在写入默认画像前明确告知用户；
- 完整展示任务摘要并等待确认；
- 不得把安装确认、授权声明或“继续”误判为任务摘要确认；
- 抓取完成后继续行情核验和分析总结，而不是只报告帖子数量。

## 安全与错误处理

- 授权默认声明可以预置为产品政策，但任务目标和任务摘要确认不能预置。
- 无草稿、草稿不完整、摘要不匹配或确认失效时，抓取必须拒绝执行。
- 外置浏览器未登录、验证码、风控或请求失败时，返回可恢复状态，不尝试绕过。
- 数据源失败必须有有限超时并降级；最终报告标注数据完整性。
- 初始化可重复执行且不得覆盖已存在的有效配置或任务草稿，除非用户明确要求重置。

## 文档与可移植性

README、WELCOME、根 `SKILL.md`、CLI 参考和 WorkBuddy 文档采用同一流程及术语。实现只依赖仓库内代码和公开声明的运行时依赖，不依赖个人目录中的 Skill。各 Agent 可以通过 CLI/JSON 操作同一个状态机。

## 测试与验收

自动化测试覆盖：

- `init --no-interactive` 不等待输入、不创建默认目标，并生成 landing；
- 默认人工 `init` 进入问答且允许安全退出；
- 不完整草稿不能确认；
- 摘要输出包含所有执行相关字段；
- 明确确认后可通过执行门控；
- 修改任一执行相关字段会使确认失效；
- 未确认请求不会调用浏览器 runner；
- README、WELCOME、Skill 和 WorkBuddy 文档包含一致的确认流程。

最终以一个全新的 clone 和虚拟环境进行验收：运行 `init --no-interactive` 后，Agent 必须先询问并确认新任务，不能自动抓取历史目标；确认后才完成真实抓取、行情核验和分析报告。
